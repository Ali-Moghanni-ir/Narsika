# بازبینی و بهینه‌سازی نارسیکا

تاریخ: ۲۰۲۶-۰۹-۱۴ — نسخهٔ محلی Beta / Workspace & Firewall Control

این گزارش مربوط به مرحلهٔ قبل از افزودن زمان‌بندی است. امکانات و نتایج نسخهٔ فعلی در [راهنمای Scheduled Tasks](SCHEDULES-FA.md) ثبت شده‌اند؛ اعداد زیر شواهد همان مرحلهٔ قبلی‌اند.

این بسته، ادامهٔ همان محصول است: Flask، Jinja، JavaScript ساده، CSS اختصاصی، SQLite و Ansible حفظ شده‌اند. ظاهر تیره/طلایی و لوگوی پذیرفته‌شده تغییر هویت نداده‌اند. بازنویسی کامل از صفر یا افزودن زیرساخت جدید انجام نشده است. هیچ دستگاه، نمودار، بکاپ یا نتیجهٔ اجرای ساختگی به نصب واقعی اضافه نشده است.

## نتیجهٔ بررسی و اصلاحات اجراشده

| بخش | مشکل یا هزینهٔ قبلی | اصلاح انجام‌شده |
|---|---|---|
| صف عملیات | دو کار یک دستگاه می‌توانستند هم‌زمان dispatch و سپس با قفل اتصال درگیر شوند | ترتیب ارسال برای هر دستگاه حفظ می‌شود؛ دستگاه‌های دیگر از ظرفیت آزاد استفاده می‌کنند |
| هم‌زمانی با Monitoring | نگه‌داشتن قفل اتصال توسط نمونه‌برداری می‌توانست کار را با BUSY شکست دهد | فقط اگر هنوز هیچ اتصال/فرمانی در آن تلاش انجام نشده باشد، کار به صف برمی‌گردد؛ فرمان اجراشده یا مبهم تکرار خودکار نمی‌شود |
| لغو اجرا | لغوِ کار منتظر به ظرفیت آزاد وابسته بود؛ شروع executor نیز نیازمند بررسی مجدد بود | تسویهٔ لغو در صف حتی هنگام پر بودن ظرفیت و بررسی لغو پیش از دسترسی شبکه |
| سلامت پردازشگر | وجود شیء worker با زنده‌بودن آن یکسان فرض می‌شد | بررسی thread واقعی در health و system؛ رد درخواست اجرای تازه با خطای ۵۰۳ در صورت توقف worker موردنیاز |
| Inventory | metadata گروه و Credential می‌توانست برای هر ردیف جدا خوانده شود | بارگذاری رابطه‌ها همراه پرس‌وجوی دستگاه‌ها |
| بارگذاری صفحه | اطلاعات Audit و فهرست همهٔ کاربران برای صفحه‌های نامرتبط بارگذاری می‌شد | bootstrap متناسب با صفحه؛ Audit از API خودش و فهرست کامل کاربران فقط در Settings |
| تاریخچهٔ اجرا | فهرست history همراه متن کامل همهٔ خروجی‌ها دریافت می‌شد | پاسخ summary در فهرست؛ خروجی کامل همچنان در جزئیات و API قدیمی موجود است |
| Credential | تغییر نام پروفایل می‌توانست ciphertext و هویت اتصال را عوض کند | ویرایش metadata، secret را دوباره رمزنگاری نمی‌کند؛ تغییر واقعی نام کاربری/secret هویت و نمونه‌ها را بی‌اعتبار می‌کند |
| کش نمونه‌ها | نام کاربری Credential در همهٔ کلیدهای نمونه لحاظ نشده بود | اضافه‌شدن نام کاربری و ciphertext به هویت نمونه؛ پاک‌سازی counter فقط برای هدف‌های مرتبط |
| تأیید عملیات | امکان کلیک تکراری و بستن زودهنگام پنجره، بدون حفظ خطای همان فرم | قفل موقت ارسال/بستن، جلوگیری از ارسال تکراری، خطای inline و تلاش مجدد آگاهانه |
| خطای ارتباط | timeout می‌توانست با شکست قطعی عملیات اشتباه شود | پیام صریح «ممکن است درخواست پذیرفته شده باشد» برای write؛ بدون retry خودکار درخواست تغییردهنده |
| رمز موقت حساب | شکست refresh پس از ایجاد/ریست کاربر می‌توانست رمز یک‌بارنمایش را از دید کاربر پنهان کند | نمایش رمز بلافاصله پس از پاسخ موفق، پیش از refresh فهرست؛ شکست refresh فقط جداگانه گزارش می‌شود |
| مجوزهای UI | بازاعمال role می‌توانست دکمهٔ مشغول را فعال کند؛ لینک دانلود برای Viewer گمراه‌کننده بود | حفظ وضعیت busy و عنوان اصلی؛ غیرفعال‌سازی مناسب لینک‌های نیازمند Operator/Admin؛ کنترل اصلی همچنان سمت سرور |
| وضعیت اجرا | هدف و مرحلهٔ کار واضح نبود و refresh، run انتخاب‌شده را از دست می‌داد | نمایش هدف/شناسه/زمان و مراحل واقعی؛ حفظ run در URL، لغو مطابق مالکیت، حفظ scroll دستی لاگ |
| درخواست‌های پس‌زمینه | poll اجرا در تب پنهان ادامه داشت و برخی پاسخ‌های قدیمی می‌توانستند وضعیت جدید را جایگزین کنند | توقف poll اجرا هنگام پنهان‌شدن صفحه، ادامه هنگام بازگشت و بی‌اثرکردن پاسخ قدیمی هدف/تب/Inventory؛ refresh پس از ذخیره از پاسخ درحال‌دریافتِ قبل از ذخیره استفاده نمی‌کند |
| شروع کار و فیلترها | صفحهٔ خالی راهنمای کافی نداشت؛ فیلتر بی‌نتیجه شبیه Inventory خالی بود | راهنمای سه‌مرحله‌ای بر مبنای دادهٔ واقعی، میان‌برهای کاری، Refresh و زمان آن، Clear filters و empty state جداگانه |
| بکاپ | انتخاب بیش از دو نسخه و مجوز مقایسه/دانلود واضح نبود | شمارندهٔ انتخاب ۰ تا ۲، پاک‌سازی انتخاب‌های ناموجود، پیام محدودیت و کنترل role |
| ظاهر | فاصله‌ها، کارت‌ها، وضعیت‌های صف و پنجره‌ها یکدست نبودند | stylesheet محلی تکمیلی، کارت‌های منسجم، تأکید طلایی محدود، ترکیب‌بندی ورود، جدول با scroll افقی و وضعیت‌های دقیق اجرا |

ظاهر همچنان برای استفادهٔ دسکتاپ طراحی شده است؛ ادعای layout محصول مخصوص موبایل/تبلت اضافه نشده است. راهنمای شروع فقط برای ادمین و تا تکمیل مراحل دیده می‌شود. زمان Refresh نشان‌دهندهٔ دریافت Inventory است، نه ادعای نمونه‌برداری جدید از تجهیزات.

## شواهد تست

| آزمون | نتیجه | دامنهٔ قابل اتکا |
|---|---|---|
| مجموعهٔ کامل pytest | ۲۲۰ موفق، یک skipped | تست‌های برنامه، امنیت، مهاجرت، نصب‌کننده، صف، فایروال و رگرسیون‌های جدید؛ نه گواهی تمام firmwareها |
| تست‌های این مرحله | ۱۳ تست جدید Python، شامل اجرای ۷ سناریوی Node | ترتیب صف، لغو پیش از اتصال، worker متوقف، cache، پاسخ کم‌حجم، مجوز و رفتار تأیید/خطا/ترتیب refresh در frontend |
| HTTP واقعی Gunicorn | PASS | bootstrap تصادفی، تغییر اجباری رمز، ۱۱ صفحه، assets/API، Inventory خالی و حفظ نوشتهٔ تست پس از restart؛ رمز تست در لاگ نبود |
| Ansible syntax-check | هر ۱۸ فایل: PASS | ۱۰ Playbook فعلی، ۶ فایل اصلی و ۲ driver داخلی؛ بدون اجرای فرمان روی تجهیزات |
| اعتبارسنجی بسته | PASS | Python AST، ۱۲ ماژول JavaScript، shell، Compose و volume، تولید config و بارگذاری واقعی factory در Gunicorn |
| وابستگی محیط تست | `pip check`: PASS | Python 3.12.14؛ این نتیجه دسترسی به هر میرور یا اجرای Python همهٔ نسخه‌ها را تضمین نمی‌کند |
| اندازهٔ history | تست رگرسیون PASS | در fixture دارای لاگ بلند، پاسخ summary کمتر از یک‌بیستم پاسخ کامل است؛ benchmark عمومی سرعت یا RAM محصول نیست |
| پرس‌وجوی Inventory | تست رگرسیون PASS | خواندن ۳۰ دستگاه با ۳۰ گروه/پروفایل، حداکثر سه SELECT در درخواست؛ جلوگیری از رشد پرس‌وجو به‌ازای هر ردیف |
| تعامل و رندر مرورگر | BLOCKED | مرورگر در بازکردن preview محلی خطای `net::ERR_BLOCKED_BY_CLIENT` داد؛ تست‌های HTTP و Node جای رندر بصری و تعامل واقعی را نمی‌گیرند |
| نصب تازهٔ Ubuntu / Windows | NOT RUN | اجرای واقعی apt، systemd، UFW، reboot، WSL و Docker Desktop در این محیط انجام نشد |
| Docker image و سرعت build | NOT RUN | Docker موجود نبود؛ بهینه‌سازی کش/میرور قبلی حفظ شده، اما عددی برای کاهش زمان ساخت ادعا نمی‌شود |
| Cisco / MikroTik و SNMPv3 واقعی | LAB_REQUIRED | اثر ترافیکی رول، دستورهای firmware، backup/restore و قطع/وصل مدیریت به Lab با دسترسی کنسول نیاز دارند |

تست skipped مربوط به transport کامل `network_cli` است؛ محیط اجرا Unix socket لازم را ممنوع می‌کند. هیچ PASS برای این بخش ثبت نشده است. رکوردها و رمزهای تست فقط در محیط‌های یک‌بارمصرف آزمون ساخته می‌شوند و داخل ZIP محصول قرار نمی‌گیرند.

برای تکرار آزمون‌ها در محیط توسعهٔ آماده:

```bash
python -m pytest -q -rs
node --test tests/frontend_core.test.cjs
python -m pip check
python tools/check_playbooks.py
python tools/validate_package.py
python tools/http_smoke.py
```

Node فقط برای آزمون/بررسی JavaScript لازم است؛ اجرای محصول به Node یا frontend build نیاز ندارد.

## نصب و استفاده از این بسته

ZIP را کامل در پوشه‌ای جدید استخراج کن. از داخل پوشهٔ `narsika`، نصب اصلی Ubuntu 24.04 یا جدیدتر روی x64:

```bash
bash run_linux.sh
```

برای ارتقای نصب موجود از مسیر نسخهٔ استخراج‌شده:

```bash
sudo narsika-admin backup
sudo narsika-admin upgrade /absolute/path/to/new/narsika
sudo narsika-admin doctor
```

فرمان backup در بالا یک بکاپ دستی پلتفرم می‌گیرد؛ بکاپ روزانه و retention خودکار فعال نشده‌اند. داده‌ها، حساب‌ها و کلیدهای `/var/lib/narsika` و `/etc/narsika` را برای حل خطای نصب پاک نکن. نصب مجدد رمز ادمین موجود را تغییر نمی‌دهد.

در Windows، فقط `run_windows.bat` ورودی کاربر است؛ فایل PowerShell داخل `tools` پیاده‌سازی همین launcher است، نه نصب‌کنندهٔ موازی دیگری. راهنماهای انگلیسی Linux/Windows در [README](../README.md) و [INSTALLATION](INSTALLATION.md)، راهنمای فارسی Docker در [DOCKER-START-FA](DOCKER-START-FA.md) و فایروال در [FIREWALL-START-FA](FIREWALL-START-FA.md) هستند.

ساخت اول Docker هنوز به دانلود Python و Galaxy نیاز دارد. تنظیم میرور برای Python، دسترسی به Galaxy/apt یا registry را حل نمی‌کند. برای راه‌اندازی مجدد image موجود از `docker compose up -d --no-build` استفاده کن؛ ارتقای سورس نیازمند build جدید است.

## حفظ سازگاری و مرز تحویل

- هیچ فایل، Route، Model، Playbook یا قابلیت موجود حذف یا rename نشده است. schema، dependency، سرویس زیرساختی و کلید config جدیدی وجود ندارد.
- قرارداد کامل bootstrap و history حفظ شده؛ شکل کم‌حجم، گزینه‌ای افزوده است. داده یا لاگ قدیمی حذف/کوتاه نشده است.
- نسخهٔ فایروال همچنان افزایشی و IPv4 است؛ بازنویسی دلخواه رول موجود، NAT و rollback زمان‌دار ادعای این بسته نیست. هشدار lockout و بازیابی دستی حفظ شده‌اند.
- صرفاً قفل اتصال پیش از کار شبکه اجازهٔ بازگشت به صف دارد؛ نتیجهٔ مبهم یا عملیات نیمه‌اجرا تکرار خودکار نمی‌شود. Cancel نیز فرمان پذیرفته‌شده توسط دستگاه را برنمی‌گرداند.
- نصب‌کنندهٔ native، بازیابی شکست UFW، تنظیم میرور و کش Docker از اصلاحات قبلی در این ZIP باقی هستند. این مرحله سرویس یا فایروال میزبان واقعی را تغییر نداده است.
- سورس کامل، فایل‌های Linux/Windows/Docker، Playbookها، README، راهنماهای فارسی و تست‌ها داخل بسته هستند. venv، DB تست، رمز، cache و خروجی‌های موقت جزو تحویل نیستند.
- این بسته برای بررسی محلی است؛ commit، push یا image جدیدی منتشر نشده است.

گام پذیرش بعدی: نصب روی یک Ubuntu VM جدا، بررسی رفتار مرورگر در نمایشگر دسکتاپ، ورود/تغییر رمز و roleها، تست restart/upgrade و شبکه‌های مجاز/غیرمجاز؛ سپس backup و یک تغییر کم‌خطر روی Cisco و MikroTik با دسترسی کنسول. تا عبور از این مرحله، صحت کامل عملیات روی شبکهٔ واقعی ادعا نمی‌شود.
