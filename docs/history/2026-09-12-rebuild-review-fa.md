# گزارش بازبینی و بازسازی نارسیکا

تاریخ: ۲۰۲۶-۰۹-۱۲ — نسخهٔ محلی Beta / Firewall Control Preview

به‌روزرسانی ۲۰۲۶-۰۹-۱۴: گزارش همین بسته و نتایج جدید در [بازبینی Workspace](WORKSPACE-REVIEW-FA.md) است. تنظیمات کش و میرور Docker در [راهنمای Docker](DOCKER-START-FA.md) ثبت شده‌اند. نتایج زیر مربوط به بازسازی ۱۲ سپتامبر هستند.

این گزارش مربوط به همین ZIP است، نه نسخهٔ فعلی GitHub. بازبینی بر پایهٔ کد موجود و تست انجام شد؛ بازنویسی از صفر، حذف قابلیت یا تغییر معماری انجام نشد. اطلاعات نمایشی فقط در تست‌های ایزوله وجود دارند و نصب واقعی با Inventory خالی شروع می‌شود.

## ایرادهای پیدا‌شده و اصلاح‌شده

| بخش | ایراد | اصلاح این نسخه |
|---|---|---|
| UFW | استفاده از شمارهٔ جایگاه و تشخیص خالی‌بودن از status برای ruleset غیرفعال قابل اتکا نبود | استفاده از `ufw prepend` بدون شماره‌گذاری؛ قواعد مدیریت روی همهٔ اینترفیس‌های IPv4 و پورت انتخابی باقی می‌مانند |
| ترتیب نصب | سرویس جدید پیش از اتمام فرمان‌های فایروال فعال می‌شد | آماده‌سازی فایروال قبل از تعویض نسخه و فعال‌سازی سرویس |
| بازیابی ارتقا | متغیر مسیر نسخهٔ قبلی با مقدار شبکهٔ مدیریت بازنویسی می‌شد | جداسازی دو متغیر؛ تست شکست عمدی و بررسی بازگشت symlink، config و launcher |
| شکست اولین نصب | بازیابی به وجود نسخهٔ قبلی وابسته بود | حفظ حساب، داده و کلید؛ انتقال فایل‌های راه‌انداز تازه به پوشهٔ تشخیص خطا در همان release |
| کلیدهای موجود | نبود config کنار DB موجود می‌توانست مسیر ایجاد کلید تازه را باز کند | توقف پیش از bootstrap و درخواست بازگرداندن config با کلید اصلی |
| دانلود Python | timeout/retry ثابت و عبور‌نکردن تنظیمات میرور از sudo | انتخاب صریح یک میرور HTTPS، محدودیت قابل تنظیم و تلاش مجدد در همان release |
| صف اجرا | تغییر رمز/دسترسی کاربر یا تغییر محتوای Credential بعد از صف‌شدن کامل بررسی نمی‌شد | ثبت و بررسی مجدد نسخهٔ نشست و fingerprint داخلی Credential پیش از اجرای عملیات |
| هشدار فایروال | مسیر پاسخ SSH با پورت مقصد SSH اشتباه گرفته می‌شد | تشخیص محافظه‌کارانهٔ احتمال قطع TCP خروجی به آدرس مدیریت، شامل پورت موقت پاسخ |
| نمایش منشأ رول | وجود متن شبیه tag به معنی مالکیت تلقی می‌شد؛ Cisco عملاً tag روی دستگاه نمی‌نوشت | تفکیک Device tag در RouterOS و Receipt match در Cisco؛ تطبیق رسید اثبات مالکیت انحصاری نیست |
| فرم فایروال | ویرایش نامعتبر بسته می‌شد؛ ارسال Apply اجازهٔ بستن زودهنگام داشت | حفظ فرم خطادار، قفل موقت هدف/بستن هنگام ارسال، پیام بررسی History در خطای پاسخ |
| ACL سیسکو | ACLهای دارای remark مبهم در انتخاب‌گر فعال بودند | نمایش فقط‌خواندنی و جلوگیری از انتخاب برای تغییر؛ محتوای موجود حفظ شده است |
| Monitoring | حذف نمونهٔ counter با کلیدی متفاوت از کلید واقعی cache انجام می‌شد | اصلاح کلید و استفاده از قفل موجود |
| VLAN | پاسخ دیرترِ دستگاه قبلی می‌توانست جدول دستگاه جدید را بازنویسی کند | شمارهٔ درخواست؛ بی‌اثرکردن پاسخ موفق یا خطای قدیمی |

نسخه‌های وابستگی در `requirements.txt` و `constraints.txt` تغییر نکردند. خطای resolver لزوماً به معنی تعارض واقعی دو نسخه نیست؛ مثلاً `SQLAlchemy==2.0.52` با شرط `>=2.0.16` تعارض ندارد. موجودبودن فایل در میرور، نسخهٔ Python و سایر پیام‌های resolver باید بررسی شوند. امکان resolve بدون نصب اضافه شده است؛ فراهم‌بودن تمام فایل‌ها روی میرور کاربر در این محیط آزمایش نشده است.

## ابزارهای تازه

### عیب‌یابی نصب موجود

```bash
sudo narsika-admin doctor
```

مسیر release، وجود و مجوز config و کلیدها، وجود DB، systemd، Python، سازگاری وابستگی‌ها، Ansible، manifest کالکشن‌ها و سلامت HTTP محلی بررسی می‌شوند. مقادیر کلید یا رمز چاپ نمی‌شوند. این فرمان سرویس را restart نمی‌کند، بسته نصب نمی‌کند و فایروال یا حساب‌ها را تغییر نمی‌دهد. بررسی وجود فایل جای بررسی صحت کل DB یا اتصال تجهیزات را نمی‌گیرد.

### میرور نصب

ZIP را کامل در پوشه‌ای جدید استخراج کن و داخل `narsika` اجرا کن:

```bash
bash run_linux.sh
```

اگر دانلود Python شکست خورد، نصاب آدرس HTTPS میرور دیگری را درخواست می‌کند. آدرس همان میروری را وارد کن که روی سیستم تو کار کرده است؛ Enter خالی نصب را متوقف می‌کند. در هر نوبت اجرا حداکثر سه تلاش نصب انجام می‌شود. timeout پیش‌فرض ۱۲۰ ثانیه و retry پیش‌فرض هر دانلود ۳ است.

تنظیمات `NARSIKA_PIP_INDEX_URL`، `NARSIKA_PIP_TIMEOUT` و `NARSIKA_PIP_RETRIES` نیز پیش از اجرای launcher پذیرفته می‌شوند. میرور خودکار انتخاب نمی‌شود، بررسی TLS خاموش نمی‌شود و pinها شل نمی‌شوند. تنظیمات pip عمومی و extra-index برای مخلوط‌نشدن منابع کنار گذاشته شده‌اند. جزئیات و فرمان بررسی dependency بدون نصب در [راهنمای نصب](INSTALLATION.md#package-downloads-and-mirrors) است. این گزینه‌ها به apt، Galaxy و Docker build تعمیم داده نشده‌اند.

## نتیجهٔ تست همین نسخه

محیط اجرا: Python 3.12.14 و Node 24.19.0؛ وابستگی‌های واقعی Flask/SQLite/Ansible در محیط ایزولهٔ محلی.

| آزمون | نتیجه | مرز نتیجه |
|---|---|---|
| کل مجموعهٔ pytest | ۲۰۷ PASS، یک SKIP؛ ۵۴٫۳۷ ثانیه | تست‌های واقعی برنامه و رگرسیون؛ I/O تجهیزات فقط در تست‌های مربوط با fixture جایگزین شده است |
| تست‌های جدید بازسازی | ۳۱ تست، در مجموعهٔ بالا | خطای نصب/ارتقا، میرور، مجوز صف، Credential، traceability، doctor و ترتیب پاسخ UI |
| HTTP واقعی Gunicorn | PASS در دو اجرای متوالی | bootstrap تصادفی، تغییر اجباری رمز، ۱۱ صفحه، API/assets، ذخیرهٔ داده و ورود پس از restart؛ رمزها در لاگ ثبت نشدند |
| بررسی Ansible | هر ۱۸ Playbook: PASS | ۱۰ فایل فعلی، ۶ فایل اصلی، ۲ driver داخلی؛ syntax-check بدون اتصال دستگاه |
| بررسی بسته | PASS | Python AST، ۱۲ ماژول JS، shell، YAML و volume داکر، config و بارگذاری واقعی Gunicorn |
| سازگاری Python نصب‌شده | `pip check`: PASS | وابستگی‌های همین محیط، نه تضمین دسترسی به هر میرور |
| بازیابی native و UFW | PASS با تزریق خطا و مدل فرمان | UFW/systemd واقعی میزبان اجرا یا تغییر داده نشدند |
| تعامل مرورگر و ظاهر | در این نوبت اجرا نشد | HTTP و تست ترتیب پاسخ Node جای تست مرورگر را نمی‌گیرند؛ مانع loopback مرورگر در گزارش قبلی ثبت شده است |
| نصب تازه Ubuntu 24.04 / 26.04 | نیازمند VM | رفتار واقعی apt، UFW، systemd، reboot و دسترسی کلاینت‌ها اینجا تأیید نشده است |
| Windows / WSL / Docker build | در این نوبت اجرا نشد | فایل‌ها و ساختار حفظ و بررسی شدند؛ محیط اجرایی آن‌ها موجود نبود |
| Cisco / MikroTik واقعی | LAB_REQUIRED | تجهیزات، نسخهٔ firmware، اثر ترافیکی رول و بازیابی از قطع SSH باید در Lab آزموده شوند |

تنها تست skipped مربوط به transport کامل Ansible `network_cli` است؛ محیط اجرای فعلی Unix socket موردنیاز آن را ممنوع می‌کند. این نتیجه FAIL محصول یا PASS اتصال واقعی محسوب نشده است.

فرمان‌های قابل تکرار پس از نصب وابستگی‌های توسعه و کالکشن‌ها:

```bash
python -m pytest -q -rs
python -m pip check
python tools/check_playbooks.py
python tools/validate_package.py
python tools/http_smoke.py
```

## حفظ سازگاری و مسیر تست بعدی

- هیچ فایل، Route، Model، Playbook یا قابلیت موجود حذف یا rename نشد؛ schema و dependency جدیدی افزوده نشد.
- رمز ادمین موجود تغییر نکرد. نصب دوباره، حساب و کلیدهای قبلی را نگه می‌دارد. پوشه‌های `/var/lib/narsika` و `/etc/narsika` را برای رفع خطای نصب پاک نکن.
- عملیات قدیمیِ صف‌شده که Credential دارند ممکن است به‌خاطر تقویت هویت هدف با `TARGET_CHANGED` متوقف شوند؛ وضعیت و تاریخچه حفظ می‌شود و باید دوباره بازبینی و ارسال شوند. عملیات از قبل تمام‌شده اجرا نمی‌شود.
- شکست نصب یک transaction کامل فایروال نیست. قواعدی که پیش از شکست اضافه شده‌اند باقی می‌مانند؛ `sudo ufw status numbered` و لاگ نصب را بررسی کن. هیچ reset خودکاری انجام نمی‌شود.
- فایروال پنل هنوز تغییرات افزایشی IPv4 را انجام می‌دهد؛ رابط toggle برای بازنویسی رول موجود، NAT و rollback زمان‌دار به این نسخه اضافه نشده است. هشدار و بازیابی دستی حفظ شده‌اند.
- ابتدا روی VM جدا نصب کن، سپس `doctor` و ورود با تغییر اجباری رمز را بررسی کن. دسترسی از یک شبکهٔ مجاز و یک شبکهٔ غیرمجاز، حفظ SSH، restart/reboot و نصب دوباره را آزمایش کن. بعد یک تغییر کم‌خطر روی هر vendor با دسترسی کنسول انجام بده.
- بسته شامل README انگلیسی، همین گزارش، راهنمای فارسی فایروال، سورس کامل، فایل‌های native/Windows/Docker و Playbookهاست. خروجی‌های موقت، دیتابیس تست و محیط Python داخل ZIP نیستند. چیزی در GitHub منتشر نشده است.
