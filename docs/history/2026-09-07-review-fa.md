# بازبینی الزامات و تصمیم اجرای نسخهٔ واقعی

> این متن سابقهٔ بررسی نسخهٔ یکپارچهٔ قبلی است. تصمیم‌های نصب، bootstrap و مرز تستِ جاری در RELEASE-NATIVE.md، INSTALLATION.md و VALIDATION.md جایگزین توضیح‌های قدیمی این فایل شده‌اند. انتشار قبلی GitHub با تأیید مالک انجام شده بود؛ این بستهٔ جدید منتشر نشده است.

نتیجهٔ بازبینی: ادامه با Flask، Jinja، CSS اختصاصی، JavaScript ساده و SQLite مناسب این نسخه است. فرانت تأییدشده قابل حفظ بود؛ بخش ذخیره‌سازی نمایشی و اجرای شبیه‌سازی‌شدهٔ آن باید به سرویس‌های سرور وصل می‌شد. بازنویسی با React یا افزودن زیرساخت جداگانه لازم نبود.

| الزام | تصمیم و پیاده‌سازی |
|---|---|
| انطباق با فرانت | همان صفحات، ناوبری، تم و فرم‌ها حفظ شدند؛ کنترل‌ها به API واقعی وصل‌اند |
| دادهٔ واقعی | هیچ دستگاه یا اندازه‌گیری اولیه تولید نمی‌شود؛ فقط پاسخ واقعی تجهیز/پایگاه داده نمایش داده می‌شود |
| امنیت پایه | ادمین از رمز تعیین‌شدهٔ مالک، تغییر اجباری رمز، نقش، CSRF، کنترل session و محدودیت تلاش ورود |
| Credential تجهیزات | رمزنگاری در ذخیره‌سازی؛ ارسال به Ansible در فایل خصوصی موقت، خارج از argv |
| هویت تجهیزات | SSH host key با تأیید fingerprint، بدون پذیرش خودکار کلید ناشناس |
| مانیتورینگ | نمونه‌برداری هنگام مشاهدهٔ صفحه؛ نمایش N/A برای دادهٔ ناموجود و تفکیک ICMP از SSH |
| Discovery | CIDR مجاز و محدود، تشخیص candidate، Verify احراز‌شده پیش از Import |
| تغییرات شبکه | تأیید در UI، اعتبارسنجی سمت سرور، بکاپ قبل از VLAN/ACL و تاریخچهٔ اجرای واقعی |
| عملیات طولانی | صف پایدار SQLite، دو thread اجرایی، timeout و لغو گروه فرایندهای Ansible |
| نگهداری داده | volume واحد با مسیر ثابت، بکاپ/Artifact رمزنگاری‌شده، مهاجرت افزایشی و snapshot |
| حفظ موارد قبلی | مدل‌ها، URLها و شش Playbook حفظ شدند؛ منبع قدیمی در تاریخچهٔ Git موجود است و آرشیو رمزنگاری‌شده از دادهٔ حذف‌شونده نگهداری محافظت می‌کند |
| اجرا و تحویل | Dockerfile، Compose، نسخه‌های dependency، راه‌اندازها، تست، مستند و یک ZIP |

بهینه‌سازی‌های انجام‌شده: حذف ذخیره‌سازی ساختگی مرورگر، polling فقط در صفحهٔ قابل مشاهده، محدود کردن اتصال‌های هم‌زمان، قفل هر تجهیز، WAL برای SQLite، اجرای عملیات خارج از thread درخواست HTTP، محدودیت خروجی لاگ، و جمع‌آوری artifact بدون ثبت خروجی محرمانه در Audit.

دو خطای اجرایی با تست پیدا و اصلاح شدند: فعال‌سازی WAL در زمان نامناسب تراکنش که راه‌اندازی مجدد را خراب می‌کرد، و اختلاف گزینهٔ فایل known_hosts بین نسخه‌های نصب‌شدهٔ netcommon و pylibssh. اصلاح دوم با hash نسخهٔ منبع کنترل می‌شود و بررسی کلید SSH را فعال نگه می‌دارد.

مرز فعلی محصول: یک سرور و یک فرایند Gunicorn؛ مقیاس افقی، تاریخچهٔ دائمی Telemetry، Topology و HA اضافه نشده‌اند. این انتخاب‌ها برای شروع عملی، پیچیدگی استقرار را محدود می‌کنند. برای ظرفیت بالاتر باید پس از سنجش تعداد تجهیزات و بار واقعی تصمیم گرفت.

تست‌های برنامه، مهاجرت، صف، callback، رمزنگاری، قالب‌ها و اتصال SSH روی loopback قابل اجرا بودند. ساخت image Docker، ورود و ماندگاری پس از restart در GitHub Actions تأیید شدند. تست نهایی Cisco/RouterOS واقعی هنوز به لَب نیاز دارد. جزئیات و وضعیت‌های دقیق در `VALIDATION.md` آمده است؛ «کد نوشته شده» با «عملیات تأییدشده روی سخت‌افزار» یکسان گزارش نمی‌شود.

برای استفاده از محصول، هیچ دسترسی جدیدی به GitHub یا حساب شخصی شما لازم نیست. میزبان اجرا باید Docker/Linux و دسترسی شبکه به تجهیز داشته باشد؛ Credential و fingerprint واقعی را خودتان داخل برنامه ثبت می‌کنید. برای اجرای تست روی لَب از این محیط نیز باید یک مسیر شبکهٔ قابل دسترس به لَب و دسترسی همان تجهیزات فراهم باشد.

بازبینی اصلاحی: محدودیت ورود فقط خطاها را نگه می‌دارد؛ ورود موفق سهمیهٔ IP را مصرف نمی‌کند و خطاهای حساب را صفر می‌کند. فرم قدیمی تغییر رمز، پاک‌سازی bootstrap پیش از Gunicorn، مهاجرت رمزنگاری‌شده با بازیابی، حفظ بکاپ اجرای ناموفق، تشخیص تغییر مقصد در صف، بازیابی نصب، HTTPS و ابزار نگهداری آفلاین اضافه یا اصلاح شدند. برای مقیاس افقی یا HA تغییری انجام نشده است؛ این‌ها جزء معماری فعلی نیستند.
