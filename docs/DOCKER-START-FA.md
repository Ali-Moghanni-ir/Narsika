# نصب و اجرای Docker — اصلاح ۲۰۲۶-۰۹-۱۳

نصب اول هنوز به دانلود image پایه، بسته‌های سیستم، Python و کالکشن‌های Ansible نیاز دارد. در این اصلاح، کش دانلود pip فعال شده، نصب کالکشن‌ها از مرحلهٔ patch جدا شده و فایل‌های موقت از build context کنار گذاشته شده‌اند. تغییر معمول کد برنامه نباید لایه‌های سالم وابستگی را دوباره بسازد؛ حذف cache یا تغییر وابستگی‌ها روی این رفتار اثر دارد.

برای نصب روی لینوکس:

```bash
bash run_linux.sh --docker
```

اگر PyPI کند یا مسدود است، آدرس HTTPS میروری را که روی سیستمت جواب داده جای دامنهٔ نمونه بگذار؛ این دامنه فقط مثال است:

```bash
NARSIKA_PIP_INDEX_URL=https://mirror.example.org/simple/ bash run_linux.sh --docker
```

روی ویندوز از PowerShell در پوشهٔ پروژه:

```powershell
$env:NARSIKA_PIP_INDEX_URL = 'https://mirror.example.org/simple/'
.\run_windows.bat
```

تنظیمات اختیاری `NARSIKA_PIP_TIMEOUT` و `NARSIKA_PIP_RETRIES` نیز به build منتقل می‌شوند؛ پیش‌فرض ۱۲۰ ثانیه و سه retry است. میرور فقط دانلود Python را تغییر می‌دهد، نه Docker Hub، apt یا Galaxy. رمز یا token را در این متغیرها قرار نده؛ URL دارای credential پذیرفته نمی‌شود. بعد از شکست build، تنظیم را اصلاح و launcher را دوباره اجرا کن؛ داخل Docker پرسش تعاملی میرور وجود ندارد. BuildKit در Docker فعلی لازم است.

پس از نصب موفق، برای اجرای معمول فقط این فرمان لازم است:

```bash
docker compose up -d --no-build
```

اجرای مجدد نصاب برای روشن‌کردن روزمره لازم نیست. هنگام ارتقای سورس از نصاب استفاده کن. فایل `.env` و volume داده را نگه دار؛ cache ساخت را بین تلاش‌های نصب پاک نکن.

خروجی build اکنون مرحله‌ها را واضح نشان می‌دهد. اگر هنوز کند بود، نام مرحله و چند خط خروجی همان مرحله را بفرست؛ مخصوصاً مشخص شود توقف روی image پایه، apt، pip، Galaxy یا انتظار سلامت سرویس است. بدون این اطلاعات نمی‌توان کندی اینترنت، build و راه‌اندازی را یکی دانست.

اعتبارسنجی این اصلاح: ۷۳ تست مرتبط با نصب/یکپارچگی/بازسازی موفق؛ بررسی بسته، JS/Python/shell و بارگذاری Gunicorn موفق. Docker و Windows اجرایی در محیط بررسی موجود نبودند؛ ساخت image و زمان نصب این نسخه اندازه‌گیری نشده است. عدد تست کامل ۲۰۷ در گزارش قبلی مربوط به بازسازی پیشین است. چیزی در GitHub یا registry منتشر نشده است.

برای حذف build از نصب اولیهٔ کاربران، مسیر آینده یک image آماده و نسخه‌بندی‌شده است. این بسته همچنان از سورس build می‌شود و image آماده‌ای همراه آن نیست.
